# 線上訂單 × Google 試算表

顧客在網站按「送出訂單」後，訂單會寫進這份試算表的「訂單」工作表：
https://docs.google.com/spreadsheets/d/1YtDO3NcpehE2O2JI1mWgBt1TiefgFMaG_z6zmhLMPNc/edit

```
網站結帳（src/d_shop.js）
   │  POST JSON（Content-Type: text/plain，避免瀏覽器的 CORS 預檢）
   ▼
Google Apps Script 網頁應用程式（gas/Code.gs 的 doPost）
   ├─ 驗證姓名、手機、門市、取餐時間、宅配地址
   ├─ 依程式內的價目表重新計價（不信任網頁送來的金額）
   ├─ 依「請求編號」防止重複建單（網路斷線後重送不會多一筆）
   └─ 寫入「訂單」工作表，狀態「已收到」
   │
   ▼  回傳 { ok, orderId, total }
網站顯示取餐單，例如 JJ20261119-001

網站取餐單／訂單查詢（src/e_track.js）
   │  GET ?action=status&id=訂單編號&tel=手機末三碼（每 25 秒一次，到「已完成」「已取消」就停）
   ▼
gas/Code.gs 的 doGet → lookup
   ├─ 編號＋末三碼都對才回傳；同一張單答錯 5 次鎖 10 分鐘
   └─ 只回傳狀態、取餐方式、門市、時間、品項、金額（不含姓名、手機、地址、備註）
```

`order-config.js` 的 `endpoint` 留空時，網站維持原本的示範模式，不會送出任何資料。

---

## 一、建立 Apps Script（約 5 分鐘）

需要用**擁有這份試算表編輯權限**的 Google 帳號操作。

1. 打開上面的試算表 → 上方選單 **擴充功能 → Apps Script**。
2. 把 `gas/Code.gs` 的全部內容貼進編輯器的 `程式碼.gs`（取代原本內容），按儲存。
3. （選用）左側齒輪「專案設定」→ 勾選「在編輯器中顯示『appsscript.json』資訊清單檔案」，再把 `gas/appsscript.json` 的內容貼進去。這樣時區會固定為台北、權限只要求試算表。
4. 上方函式選單選 **setup** → 按 **執行**。它會建立工作表、幫「狀態」欄加上下拉選單與顏色。第一次會要求授權：
   選帳號 → 看到「Google 尚未驗證這個應用程式」時，點 **進階 → 前往（不安全）** → 允許。這是你自己寫的程式，所以 Google 沒有審核過。
5. 回到試算表，會多一個 **訂單** 工作表，第一列是標題。

## 二、部署成網頁應用程式

1. Apps Script 右上角 **部署 → 新增部署作業**。
2. 左邊齒輪選 **網頁應用程式**，設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**（顧客不用登入 Google 就能下單）
3. 按 **部署**，複製「網頁應用程式網址」，結尾是 `/exec`。
4. 用瀏覽器打開這個網址，看到 `{"ok":true,"service":"煎記鍋貼訂單",...}` 就代表程式在運作。

## 三、接上網站

打開專案根目錄的 `order-config.js`，把網址貼進 `endpoint`：

```js
window.JJ_ORDER_CONFIG = Object.freeze({
  endpoint: 'https://script.google.com/macros/s/……/exec'
});
```

存檔後 commit、push，GitHub Pages 更新後就會開始收單。這個檔案獨立於 `index.html`，改網址**不用**重新執行 `build.py`。

> 部署網址本來就會公開在網頁上，沒有關係。它只能新增訂單，以及在提供「訂單編號＋手機末三碼」時查詢該筆訂單的狀態與品項；不會回傳顧客姓名、手機、地址，也無法列出其他訂單。

## 四、測試

到網站加幾樣餐點 → 結帳 → 填寫資料 → 送出。成功時結帳視窗會變成取餐單，顯示 `JJ年月日-流水號` 的訂單編號，試算表也會多一列。失敗時表單會保留，紅框顯示原因，購物車不會被清空。

接著到試算表把這筆的「狀態」改成「製作中」，約 25 秒內網站上的取餐單就會跟著變；改成「可取餐」時，就算顧客關掉了取餐單，頁首也會出現橘點並跳出提示。

也可以直接用瀏覽器測查詢：在部署網址後面加上 `?action=status&id=JJ20261119-001&tel=678`（換成實際的編號與手機末三碼）。

## 店員怎麼更新進度

在「訂單」工作表點該筆的「狀態」儲存格，從下拉選單選：

| 狀態 | 顧客取餐單顯示 |
|---|---|
| 已收到 | 訂單收到了（水墨生鍋貼） |
| 製作中 | 鍋貼下鍋了／宅配：急速冷凍中（半色調） |
| 可取餐 | 起鍋了，請來取餐（霓虹，頁首亮橘點並提示） |
| 已出貨 | 宅配用，禮盒已出貨（霓虹） |
| 已完成 | 取餐完成／已上桌／已送達（蓋章），網站停止查詢 |
| 已取消 | 訂單已取消，網站停止查詢 |

內用訂單的「可取餐」代表起鍋、準備上桌。

## 之後要修改時

| 情況 | 要做的事 |
|---|---|
| 改菜單價格、新增或刪除品項、門市 | `src/d_shop.js` 和 `gas/Code.gs` 的 `MENU`／`STORES` **兩邊都要改**，然後重新部署（見下一列） |
| 修改了 `Code.gs` | **部署 → 管理部署作業** → 鉛筆圖示 → 版本選「新版本」→ 部署。這樣網址不變，不用改 `order-config.js` |
| 想換一份試算表 | 改 `Code.gs` 最上面的 `SPREADSHEET_ID`，再重新部署 |
| 想暫停收單 | 把 `order-config.js` 的 `endpoint` 改回 `''` |

「狀態」欄寫入時是「已收到」，之後由店員從下拉選單更新，程式不會覆蓋。之前已建立的試算表，更新 `Code.gs` 後再執行一次 **setup** 就會補上下拉選單與顏色（重複執行沒關係）。

## 試算表欄位

下單時間、訂單編號、狀態、取餐方式、門市、取餐時間／到貨日、人數、姓名、手機、宅配地址、品項、件數、小計、運費、總金額、備註、請求編號

「請求編號」是網頁產生的亂碼，用來辨識重送的同一筆訂單，不需要理會。

## 個資提醒

這份試算表會存放顧客的姓名、手機和地址。請在試算表右上角 **共用** 把「一般存取權」改成 **「限制」**，只加入需要看訂單的人。Apps Script 以「我」的身分執行，所以改成限制後網站仍可正常寫入。
